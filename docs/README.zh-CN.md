# Off-Ball Lens：无球接应机会解释器

[打开交互 Demo](https://cabbage1999.github.io/Off-Ball-Lens/) · [英文 README](../README.md) · [方法](method.md) · [文献审查](research.md)

本项目实现此前规划中的核心链条：**独立合成的全员轨迹 → 可解释接应机会指数 → 同初态短时路线比较 → 带证据的解释 → 二维同步回放**。

这是可行性 Demo，不是经真实比赛验证的无球价值模型。指数不是概率，个人变化不是球队总贡献，固定其他人的轨迹也不能证明真实牵制因果效果。

## 使用

需要 Node.js 22 或以上。无需安装第三方依赖：

```sh
git clone https://github.com/cabbage1999/Off-Ball-Lens.git
cd Off-Ball-Lens
npm start
```

打开 `http://127.0.0.1:4173`，点击右上角“中文”。在线静态版直接在浏览器运行，不能调用服务器上的 Azure 接口。

先按“开始引导演示”依次检查三个场景，再自行拖动时间轴。建议重点检查：

- “完全相同路线”的平均差值必须为零。
- 改变比较起点后，两条路线仍从相同位置和速度开始。
- 比较窗口在首次传球前停止，不能继续固定原传球轨迹评价另一接应路线。
- “跑入封锁区”提供跑动降低指数的反例。
- “启动过早”中的零指数要区分“有限候选未通过到位检查”和“出球时越位位置”。
- “球队最佳接应选项”不等于 A7 的个人指标，更不能等于所有个人变化之和。
- 改变球速、反应时间，检查假设敏感性。显示的是逐项扰动范围，不是置信区间。

## 已实现与未验证

已实现三个 16 秒、10 Hz、22 人场景；A7 全程不触球；当前帧分析；三种替代路线；窗口平均与证据帧；球迷/分析师模式；中英文；参数敏感性；JSON 导出；确定性本地解释；可配置的 Foundry 工具调用接口。

用户已选择本轮先交付离线 Demo。**真实 Microsoft Foundry 调用未实测**，不会把本地模板或模拟接口测试冒充云端成功。按英文 README 在本机配置 `.env` 后，可以运行单独的云联调脚本。密钥不得放入前端或提交到 GitHub。

对抗审查发现并推动修正了候选点随速度扩大、接应者离圈再返回时准备程度高估、可行防守路线被追赶控制器漏掉、无有效比较窗口的云结论、服务器并发计数等问题。最终结果与证据以当前代码及验收报告为准。

运行 `npm test` 检查回归与独立验收，`npm run validate` 检查数据和场景，`npm run benchmark` 测量本机性能。测试通过证明软件与已列不变量符合要求，不证明它对真实战术价值具有预测准确率。
